Prior art: how agent harnesses detect tool-call loops先行实现：各家 Agent 如何检测工具调用循环

A source-level review of 14 agent harnesses, HEAD-pinned (October 2026). Self-contained: we read every mechanism below in the project's own repository at the recorded commit.对 14 个 Agent 工具的源码级调研，HEAD 核实（2026 年 10 月）。本文自包含：以下每条机制均在对应项目的仓库中按所记录的 commit 实读确认。

1. Why this review exists1. 调研由来

In a real session, an agent polled the same three git commands about 200 times over ~87 minutes. It kept going after the user interrupted, and only stopped when the user switched models. The commands rotated (status → diff --stat → diff file), so no three consecutive calls ever matched. That shape — periodic rotation — is what most existing detectors miss. We reviewed how other harnesses detect loops before designing our own.一次真实会话中，Agent 在约 87 分钟内轮询同三条 git 命令约 200 次，用户打断无效，最后靠切换模型才停止。这些命令是轮换的（status → diff --stat → diff file），任意连续三次都不相同。这种「周期轮换」形态正是多数现有检测器漏掉的。因此在设计自己的检测器之前，我们先调研了各家的做法。

2. The incident's shape: from chaos to a metronome2. 事故的形态：从混沌到节拍器

We encoded the 200 loop calls into four symbols. S=git status --short (85), D=git diff [file] (53), T=git diff --stat (49), V=variants (13). The timeline shows three clear phases:把 200 次循环调用编码为符号：S=git status --short（85 次）、D=git diff [file]（53 次）、T=git diff --stat（49 次）、V=写法变体（13 次），时序呈现三个相位：

  • Chaotic probing (calls 0–30, ~6 min). All 13 command variants occur here. The model is trying new spellings to prove it is doing something new.混沌试探（第 0–30 次，约 6 分钟）。全部 13 个变体都集中在这里，模型在「换花样自证」。
  • Period-3 rotation (calls 31–63, D→S→T ×11). The first stable cycle, 33 calls with zero variants.周期 3 轮换（第 31–63 次，D→S→T ×11）。第一次收敛出稳定循环，33 次调用零变体。
  • Period-4 metronome (calls 64–199, S→D→S→T ×34, 68% of the loop). 136 calls over ~30 minutes. Both user interrupts land inside this phase and do not even shift the phase. The model's actions no longer follow the input.周期 4 节拍器（第 64–199 次，S→D→S→T ×34，占循环 68%）。136 次调用约 30 分钟。两次用户打断都落在这一段，连相位偏移都没有——模型的行动已与输入脱钩。

The important consequence: entropy decreases over time. Variants vanish after the first 15% of the loop. The model does not get messier, it gets more regular. A detector based on spotting variation or on adjacent repeats cannot see the metronome phase at all.关键推论：熵随时间下降——变体在开头 15% 之后归零。模型不是越转越乱，而是越转越「整齐」。靠「识别变化」或「相邻重复」的检测器，在节拍器相位里完全失明。

9. Cross-cutting patterns9. 横向规律

  1. "3" is the shared warning threshold across opencode, kimi-code, deepseek-harness and Codex's goal mode.「连续 3 次」是各家警告档的共同起点（opencode、kimi-code、deepseek-harness、Codex goal 模式）。
  2. Two philosophies: hard breakers (kimi-code stops the turn at 12, Codex marks the goal blocked) vs soft reminders (deepseek-harness never blocks, opencode asks). Unattended runs defeat soft reminders.两派哲学：硬熔断派（kimi-code 到 12 停 turn、Codex goal 置 blocked）与软提醒派（deepseek-harness 绝不拦截、opencode 问用户）。无人值守场景下软提醒会被绕过。
  3. Scope decides effectiveness. The v1 detector failed because real loops run one or two calls per message across many messages. kimi-code's cross-step streak is the only design that held up against that shape.检测范围决定有效性。v1 检测器败在「单条消息内」——真实死循环都是跨消息、每轮一两个调用。kimi-code 的跨 step streak 是唯一能经得起这种形态的设计。
  4. Variant escape. Decorative variants bypass byte-level input comparison (echo "---" separators, quoting). Key sorting fixes attribute order only, not command-string variants.变体逃逸。逐字节比对会被 echo "---" 这类装饰变体绕过；参数 key 排序只解决属性序，不解决命令字符串级变体。
  5. The need is general. Claude Code and Codex keep adding guards for specific no-progress shapes. But nobody offers a general tool-call-level detector with output-identity gating and no window.需求是普遍的。Claude Code 与 Codex 都在为特定的无进展形态补洞，但「工具调用级 + 输出一致性 + 无窗口」的通用检测，目前没人做。

10. Design positioning: the one hard difference10. 设计定位：最硬的那条差异

Window size must be at least threshold × rotation period, or the block tier is dead code. OpenClaw's window of 30 calls and block tier of 20 can never catch a period-4 rotation (the measured max streak is 15). gemini-cli avoids this with exact period matching, at the cost of firing on any variant. Our signal A has no time window at all. Each signature stores only its last output hash and its streak. A period-4 signature climbs to 85 repeats. Memory is O(number of signatures), cost per call is O(1), and we never read history.窗口大小必须 ≥ 阈值 × 轮换周期，否则拦截档就是死代码。OpenClaw 窗口 30、拦截档 20，在周期 4 轮换下够不着（实测单签名最大 streak 15）。gemini-cli 靠精确周期匹配绕开，代价是一个变体就打断。我们的信号 A 不设时间窗口：每个签名只存「上次输出哈希 + 当前 streak」，所以周期 4 的签名能一路累到 85 次。内存 O(签名数)、单次调用 O(1)、不读历史库。

The replay numbers behind that claim: on the incident, gemini-cli fires at call #45. OpenClaw never reaches its block tier. Our B fires at #12 and A at #21. We do not need to claim that nobody did this before — the four numbers carry the argument.支撑这条的实测数字：同一份事故序列上，gemini-cli 在第 45 次调用触发，OpenClaw 永远到不了拦截档，我们的 B 在第 12 次、A 在第 21 次触发。我们不需要声称「没人做过」——四个数字本身就构成论据。

Two more positioning choices. Thresholds: 3 is the shared warning level. Block levels vary widely (Cline 5, Roo 3, OpenClaw 20). We warn early and keep the block tiers conservative. Escalation: gemini-cli injects feedback first and only asks the user on the second hit. Our tiers do the same. The model gets warnings before the user is ever prompted.另外两条定位。阈值：3 是各家共同的警告起点，但拦截档差异很大（Cline 5、Roo 3、OpenClaw 20），所以我们早警告、拦截档保持保守。升级方式：gemini-cli 先注入反馈、第二次才问用户；我们的档位也一样——先给模型警告，再轮到用户。

11. What we adopted, and what we deliberately rejected11. 我们采纳了什么，刻意拒绝了什么

  • Per-signature counting, not consecutive matching. Cline, Roo Code, crewAI, AutoGPT and the opencode v1 detector all compare only adjacent calls, so a rotation never trips them. Our signal A keeps one streak per signature, so interleaving never resets it.按签名计数，而非连续全等。Cline、Roo Code、crewAI、AutoGPT 以及 opencode v1 的检测器都只比相邻调用，轮换永远凑不出连续全等。我们的信号 A 给每个签名独立计数，穿插调用不清零。
  • Output identity as the gate. OpenClaw and takt showed that output hashes belong in the predicate. Signal A counts a repeat only when the output is byte-identical. A read-edit-test cycle with real progress never builds a streak.输出全等作为累计门槛。OpenClaw 与 takt 证明了输出哈希应进判定。信号 A 只在输出逐字节相同时才累计，因此 read-edit-test 这类有真实进展的循环不会累计 streak，天然避免误伤。
  • Tiered thresholds with a circuit breaker (from kimi-code's 3/5/8/12): warn early, ask surgically, hard-stop only when nobody responds.分级阈值加熔断（来自 kimi-code 的 3/5/8/12）：早警告、手术式询问、无人应答才硬停。
  • Failure equivalence as its own signal. OpenClaw's failure-identity hash inspired signal C: same tool + same normalized error, not reset by other tools' successes.失败等价作为独立信号。信号 C 借鉴 OpenClaw 的失败等价哈希：同工具 + 同归一化错误，穿插其它工具成功不清零。
  • Rejected: hard reset on user messages (gemini-cli). An interruption must not hand the loop a fresh counter. In our incident, the model kept polling for another 138 calls after the user interrupted.拒绝：用户消息硬清零（gemini-cli）。插话不能给循环发新计数器——我们的事故里模型在用户打断后又轮询了 138 次。
  • Rejected: remind-only enforcement (deepseek-harness). In our incident the model acknowledged the loop in its own reasoning and kept going, so reminders alone are not enough.拒绝：只提醒不拦截（deepseek-harness）。我们的事故中模型在推理里承认了循环却仍继续，说明只提醒不够。
  • Rejected: LLM-judged loop detection (gemini-cli's third layer). Cost, latency and nondeterminism. Our detector stays a zero-dependency pure module.拒绝：用 LLM 判定循环（gemini-cli 第三层）。成本、延迟与不确定性都不可接受，我们的检测器保持零依赖纯模块。
  • Rejected: kill on the first hit. Enforcement goes through the existing permission ask, so intentional polling always has an escape hatch.拒绝：首次命中即掐死。所有拦截都走现有权限询问，有意轮询总有逃生口。
